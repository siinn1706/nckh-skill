## Opt-in agent command adapters

The [evaluation entrypoint](../evals/run-evals.py) also supports
`--prepare-agent-run --recipe FILE` and `--run-agent --recipe FILE`.
Preparation is read-only and prints a canonical `plan_hash`. Execution additionally
requires `--allow-provider --approve-plan-hash HASH`, after the human has actually
authorized that provider/billing scope and reviewed the exact preview. A recipe,
freeze reference or approval string is data, not a new human grant.

Preview and summary receipts expose the executable, argument count and command
hash. The full argument array stays in the private command record; it is never
copied into CLI output or an `--output` summary. Review the original private
recipe as well as the preview before approval. Keep secrets out of arguments
when the chosen host supports its own credential store or environment.

One command transport covers the eight declared surfaces. The operator selects
an actual executable/bridge and pins its interface evidence, executable and bridge
files. No default provider, model, SDK, credentials, plugin trust or native
interface is invented. A declared surface does not prove that its driver is a
native agent. Unsupported interfaces remain NOT_CALLABLE/unverified.

The recipe is a closed object with these fields:

| Field | Contract |
|---|---|
| `schema_version` | Integer `1`. |
| `surface`, `host_version` | One target surface and its observed version. Unknown version blocks dispatch. |
| `argv`, `executable_sha256` | Literal argument array beginning with a real absolute executable; no shell command string or `.cmd`/`.bat` interpolation. |
| `driver_references` | Array of `{path, sha256}` for bridge scripts/dependencies. Direct script arguments must be pinned here. |
| `interface_reference` | `{path, sha256}` for the observed interface/help/binding record. |
| `transport` | `prompt-stdin` or `json-stdin`; no prompt insertion into shell text. |
| `workspace`, `private_store` | Existing absolute directories; the private store is outside the package/project and agent workspace. Preserve its approved access controls. |
| `case_ids` | Explicit unique IDs from the frozen skill cases; never implicitly select all skills. |
| `round`, `timeout_seconds` | Development round 1–3 and explicit per-case timeout 1–900 seconds. Cross-run lineage still needs protocol review. |
| `requested_model`, `requested_effort` | Explicit declarations, including `inherit`; resolution/effectiveness remain unknown without native evidence. |
| `freeze_references` | Six `{path, sha256}` or pending `null` entries: `metrics`, `sample_rights`, `reviewers`, `quality_thresholds`, `provider_budget`, `acceptable_economics`. Any pending entry blocks execution. |

Freeze-reference hashes establish integrity only. The caller must verify actual
rights, reviews, thresholds and authority before using the execution flags.
The provider-budget reference is a closed JSON object with `schema_version: 1`,
`kind: provider-run-budget`, `scope: {source_lock_hash, case_ids}`,
`mode: time-and-case-bound-unknown-cost`, `unknown_cost_accepted: true`,
`max_cases`, `max_seconds_per_case` and a nonempty `funding_scope_reference`.
Its scope covers every selected case and current source. This adapter enforces
case/time bounds, not a monetary billing cap; requests for an unsupported billing
cap or unknown budget fields stop before dispatch. Unknown-cost acceptance must
come from the human.

The runner rechecks source, case, executable, bridge and freeze hashes before
each dispatch and after execution. Raw stdout/stderr and the run journal stay in
the private store. The journal tracks selected command/workspace/PID and attempt
status; no oracle, expected-outcome labels or holdout labels enter the JSON input.
These are development cases only; protected holdout execution is unavailable.

Process exit zero produces `completed-unreviewed`, with evidence class
`unclassified-command-observation`, zero accepted tasks and unknown cost/model.
It cannot be used as an accepted native/agent/human receipt. An independent review
must verify the driver, real tool/egress traces, outcomes and model telemetry.
Failure, timeout and interruption retain their actual incomplete state; no retry
or automatic best-of-N run is added.

A case-read failure after preview also closes the private run with a failed
outcome. A lifecycle wait failure records `timeout-unknown`, an unknown exit
status and unverified cleanup. The caller must reconcile its private process
journal before another attempt. Lifecycle exception summaries omit command
arguments, which may contain private values.

Owned processes run in a Windows Job Object or POSIX process group. On Windows,
the child is created suspended, assigned before resuming, and its owned job is
closed after the attempt. This follows the documented [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)
and [ResumeThread](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-resumethread)
interfaces. Local subprocess fixtures test lifecycle/transport only; they do not
qualify native host behavior, macOS/Linux or scientific/human output.
