# Release gates

Current decision: **NO-GO for stable qualification or public distribution**.
Local build/test authorization permits an experimental candidate only.

- Local verification gate: require matching pass receipts in the [candidate record](../evals/results/candidate.json), including full deterministic checks and reproducibility.
- [ ] Clear every advertised host/surface/version/mode and OS installation cell.
- [ ] Run frozen agent cases and matched baselines under explicit authority.
- [ ] Freeze sample rights, human/domain reviewers, thresholds and protected holdout.
- [ ] Clear VI taste, EN/domain fidelity and actual native scientific visual gates.
- [ ] Establish measured cost coverage and acceptable economics before cost claims.
- [ ] Resolve redistribution/license rights; public availability is insufficient.
- [ ] Authorize real installation/migration and preserve an observed cleanup receipt.
- [ ] Obtain explicit publish/distribution authority for the exact candidate.

Do not mark pending gates pass, delete cells, shrink the approved scope, or rename
the aggregate state to hide incomplete acceptance. A local candidate includes
source/closure hashes and separate plugin lifecycle fields. Evidence remains
revision-bound; run only checks affected by a later change and preserve old receipts.

Use the [source lock](../core/registry/source-lock/source-lock.json), generated
`dist/HOST/manifest.json`, [qualification protocol](../evals/protocols/qualification.json)
and actual local receipts for candidate identity. `dist` is generated and must
not contain manuscripts, corpora, raw provider transcripts, holdout labels,
customer/contact data or credentials.
